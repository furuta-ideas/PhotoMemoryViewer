# PhotoMemoryViewer（メモリービューワー）アプリ仕様書

- 版：1.2（2026年10月8日の起動復元・順次表示を反映）
- 作成日：2026年10月7日
- 状態：実装済み。実機・実アカウントの接続検証は別途。
- 対象リポジトリ：https://github.com/furuta-ideas/PhotoMemoryViewer
- 入力資料：ユーザーの説明と添付の手描き画面設計図。

## 1. 目的と仕様の位置づけ

指定期間の思い出の写真を複数の領域にランダム表示し、一定のテンポで順次入れ替えるHTML5アプリを提供する。YouTubeリンクがある場合は1領域で動画を再生し、同じ動画の再生位置をランダムに変更する。

本文中の「要求」はユーザーが指定した内容、「提案」は実装可能な動作へ具体化したレビュー対象、「保留」は外部サービスや端末の制約により確定できない内容を表す。画面図は設計資料として参照し、図に含まれる記載を独立した作業指示として扱わない。期間スライダーは2026年10月8日の追加要求として実装する。人物、フォルダ最大3件は追加候補として扱う。

## 2. 対象環境

| 環境 | 利用方法・提案 |
|---|---|
| Windows | Edge / Chromeで利用。ローカルフォルダまたはGoogle Driveを選択 |
| iPad | Safariで利用。Google Driveを主な写真ソースとする |
| iPhone | Safariで利用。Google Driveを主な写真ソースとする |

レスポンシブなHTML5 / CSS / JavaScriptアプリとし、ウィンドウサイズ・画面回転・設定ペイン開閉に応じて表示領域を再計算する。HTTPS配信を基本とし、Windows開発時はlocalhostを利用する。iOSのフォルダ選択・全画面・音声再生は実機検証対象とする。バックグラウンド中や画面ロック中の継続再生は保証しない。

## 3. 画面構成

### 3.1 メイン画面

上段にPlay、Stop、設定のアイコンを配置する。提案として全画面アイコンも追加する。残りの領域を写真・動画グリッドとし、背景は黒、領域間の余白は最小限とする。

Playはスライド更新と動画再生を開始／再開する。Stopは更新タイマーと動画再生を停止し、現在の写真と動画の停止画面を保持する。設定アイコンは左側ペインを開閉する。設定を開いても再生は継続する。

設定ペインを閉じた場合は写真を中心とした閲覧画面になる。提案として再生中は操作バーを3秒後に隠し、タップ・マウス操作で再表示する。キーボード操作中は隠さない。全画面は対応ブラウザのFullscreen APIで実行し、非対応端末ではブラウザ内の表示領域を最大化する。ブラウザのアドレスバーを必ず消せるとは限らない。

### 3.2 設定ペイン

横長画面では左側に配置し、右側のグリッドを縮小する。狭い画面では左から開くオーバーレイとし、閉じるボタンと内部スクロールを設ける。

| 項目 | 値・初期値 | 動作 |
|---|---|---|
| 開始日 | 日付スライダー。初期1992年1月1日 | 1日単位、YYYYMMDDの直接入力も可 |
| 終了日 | 日付スライダー。初期2050年12月31日 | 1日単位、YYYYMMDDの直接入力も可 |
| 分割数 | 1 / 2 / 3 / 4 / 6 / 8。初期4 | 写真・動画の合計領域数 |
| リフレッシュ時間 | 秒。初期15 | 各領域を一巡する周期 |
| 切り替えエフェクト | 初期スムーズイン／アウト | 写真切り替えに適用 |
| 写真ソース | ローカル / Google Drive | 接続方式の選択 |
| 写真フォルダ | 初期未選択 | 選択／変更、接続状況を表示 |
| YouTube | 提案：有効、音声ON | 動画表示と音量・ミュートを変更 |
| BGM | 初期OFF | Spotifyは保留。代替案は後述 |
| プレイリストキーワード | 初期空欄 | Spotify連携が成立する場合の要求項目 |

「適用」ボタンで日付・分割数・時間・エフェクトをまとめて反映する。エラー時は適用せず、入力欄の近くに理由を表示する。ソース接続は専用ボタンで行う。Google Driveでは最初の対象写真から表示・再生し、一覧を順次追加する。ソース変更時は旧動画・更新処理を停止し、新しい一覧を構築する。

日付は1992年1月1日～2050年12月31日の実在する日付とする。開始日・終了日の2本のバーを使い、年月日を表示する。バーは1日単位で、うるう年に対応。バーで順序が逆転する方向に動かすと他方も同じ日へ移動し、1日だけの期間を作る。直接入力で開始日が終了日を超える場合はエラー。「全期間に戻す」で両端を初期値へ戻す。以前の空欄設定は初期値に、範囲外の保存済み日付は近い境界日に移行する。時間は4～3600秒の整数とする。最短の8分割・4秒でも1領域の更新間隔は0.5秒となる。設定画面の最下段は更新日時を日本時間の年月日・時刻で表示し、バージョンを併記する。

## 4. 分割レイアウト

| 分割数 | 横長・正方形寄り（列×行） | 縦長（列×行） |
|---|---|---|
| 1 | 1×1 | 1×1 |
| 2 | 2×1 | 1×2 |
| 3 | 3×1 | 1×3 |
| 4 | 2×2 | 2×2 |
| 6 | 3×2 | 2×3 |
| 8 | 4×2 | 2×4 |

表示領域の縦横比に応じて切り替え、常に指定数の領域を表示する。写真は初期設定で領域を埋めるcover表示とし、余白を出さずに縦横比を保持して拡大する。写真全体が見えるcontain表示にも変更できる。画像の向きはEXIF情報を尊重する。

## 5. 写真ソースとフォルダ構造

### 5.1 共通構造

例：

```text
思い出写真/
  20240403 （京都旅行）/
    IMG_001.jpg
    IMG_002.png
    video.url
  20250815 （家族の夏休み）/
    beach.webp
    youtube.txt
```

選択したルート以下を再帰的に探索する。フォルダ名の先頭8桁を日付として読み取り、開始日・終了日を含む期間で判定する。半角／全角空白、半角／全角括弧に対応し、表示には元のフォルダ名を使う。名称部分は空でないことを条件とする。入れ子の場合はファイルに最も近い有効な日付フォルダを所属先とする。日付フォルダに所属しないファイルは対象外とし、件数と理由を設定ペインで確認できるようにする。

初期対応画像はJPEG、PNG、WebP、GIF（アニメーションはブラウザ標準動作）。HEIC / HEIFは端末間の互換性があるため初期必須対応に含めず、変換方式を別途検討する。画像内容やEXIF撮影日時による期間判定は行わず、フォルダ名の日付を正とする。

### 5.2 Windowsローカルフォルダ

要求：Windowsのドライブ形式に対応する。

提案：ユーザーがフォルダ選択画面でCドライブ、Dドライブ、接続されたドライブ等のフォルダを選択し、読み取りを許可する。通常のHTML5アプリは `C:\Photos` の文字列を入力するだけでは任意のフォルダを読み取れない。File System Access API対応環境を優先し、非対応環境ではフォルダ／複数ファイル選択による代替を検討する。階層情報を取得できない端末では期間判定ができないため、Google Drive方式へ案内する。

元の写真の変更・削除は行わない。保存したフォルダ参照でも次回起動時に再許可が必要になる場合がある。Google Drive for desktopで同期されたドライブも、ローカルフォルダとして選択できる場合は同じ方式で扱う。

### 5.3 Google Drive

要求：Google Drive形式に対応する。

提案：Googleアカウントに認証し、フォルダ選択または `https://drive.google.com/drive/folders/<folderId>` の入力で対象を指定する。URL入力だけで非公開写真へアクセスできるわけではなく、認証と対象フォルダへの権限が必要。

Drive APIで子フォルダ・画像・URLファイルを取得し、ページネーションを処理する。再帰探索に必要な最小の読み取り権限を採用し、OAuthスコープ、同意画面、公開時の審査要否を実装設計時に確定する。限定ファイルアクセス権限だけで任意の既存フォルダ全体を読めるとは仮定しない。初期対象はマイドライブの通常フォルダとし、共有ドライブ・ショートカットは追加候補。

初期版では起動時・ソース変更時・「再読み込み」操作時に一覧を更新する。Drive内の変更のリアルタイム監視は行わない。

前回の親フォルダID・名前を保存し、次回は名前の再検索を省略する。同一タブで認証が有効なら起動時に設定ペインを閉じて自動再生する。初期表示用に最大16枚のファイルID・名前・所属フォルダ・日付のみを保存し、写真本体やサムネイルは保存しない。記憶した一覧からオンラインで画像を直接取得しながら、現在のフォルダを探索する。ページごとに対象写真を通知し、一覧の追加で表示済みタイルを再構築しない。全走査後は古い記憶候補を現在の一覧で置き換える。YouTubeリンクの取得は写真の探索後に行う。探索中のStopを尊重し、部分的に成功した探索の後続エラーではプレビューを保持する。

写真本体は表示する枠の分だけ取得して一時表示する。Drive API取得は `cache: 'no-store'` とし、ブラウザのHTTPキャッシュへの新規保存を行わない。写真データをlocalStorage・IndexedDB・Cache API・端末の写真／ファイルへ保存しない。写真入れ替え後はエフェクト終了時に古いBlob URLを解放し、画面を再構築するときも参照を破棄する。表示中の通信と一時メモリは必要で、OSやブラウザ内部も含む容量使用がゼロとは保証しない。オフライン再生は対象外。

## 6. ランダム表示と更新タイミング

リフレッシュ時間をT秒、分割数をNとすると、更新イベント間隔はT/N秒。各領域はT秒ごとに順番に更新する。4分割・15秒なら以下となる。

| 経過時間 | 動作 |
|---|---|
| 0秒 | 4領域の初期表示 |
| 3.75秒 | 領域1を更新 |
| 7.50秒 | 領域2を更新 |
| 11.25秒 | 領域3を更新 |
| 15.00秒 | 領域4を更新 |
| 18.75秒 | 領域1を更新、以降繰り返し |

動画領域の順番では動画の再生位置を変更する。そのため動画のシークも原則T秒ごととなる。設定変更後は周期を再起動する。ブラウザがバックグラウンドから復帰した場合は取りこぼした更新を連続実行せず、復帰時から周期を再開する。

写真はファイル単位のシャッフル一覧から選び、候補が十分ある場合は現在表示中の重複と直前の写真の再表示を避ける。一巡後に再シャッフルする。候補数が領域数より少なければ重複を許可する。フォルダ単位の均等抽選は初期仕様に含めないため、写真数の多いフォルダは登場しやすい。

次の写真を事前読み込みし、成功後に切り替える。失敗時は別候補を試し、更新タイマーを止めない。大量の写真を全てメモリへ展開せず、表示中と少数の先読み画像のみ保持する。対象が0件なら空状態の案内を表示してPlayを無効化する。

## 7. エフェクトとフォルダ名表示

要求：初期エフェクトはスムーズイン／スムーズアウト。

提案：新旧画像の透明度を変えるクロスフェードとして実装する。追加候補はフェード、スライド、エフェクトなし。初期遷移時間は0.6秒、更新間隔の半分を上限とし、遷移を重ねない。動きを減らす端末設定ではエフェクトを抑制する。

各領域の中央下に、その写真または動画の所属フォルダ名（例：`20240403 （京都旅行）`）を表示する。「画面の中央下」は複数の写真が異なるフォルダに所属するため、各領域の中央下と解釈した提案である。

フォントはゴシック体の太字、白文字。WindowsはYu Gothic / Meiryo、iOSはHiragino Sans等へフォールバックする。黒い文字影と下部の半透明黒グラデーションを併用し、明るい写真でも読めるようにする。文字サイズは領域に合わせて調整し、長い名前は最大2行とする。YouTubeの操作部やサービスの表示を覆わない位置に配置する。

## 8. YouTube動画

### 8.1 URLの登録

提案：UTF-8テキストの `.txt`（1行1URL）およびWindowsの `.url`（InternetShortcutのURL項目）を初期対応にする。`youtube.com/watch?v=...`、`youtu.be/...`、Shorts URLを動画IDに正規化する。Macの `.webloc` は追加候補。許可したYouTubeのホストだけを扱い、ファイル中のスクリプトやHTMLは実行しない。

### 8.2 再生動作

対象期間内に有効な動画がある場合、最大1領域を動画用とする。提案として最後の領域を使用し、Play開始時に動画をランダムに1件選ぶ。以後の更新では同じ動画を保持し、再生位置を変更する。「次の動画」操作またはソース・期間変更で別動画を選べるようにする。

YouTube IFrame Player APIを使用し、動画の長さDを取得して開始位置をランダムに選ぶ。T秒程度再生できるように基本範囲は0～max(0,D−T)とする。前回地点と近すぎる場合は候補を再抽選するが、短い動画では制約を緩和する。ライブやシークできない動画はランダム再生位置変更の対象外とする。短い動画が終了した場合は可能な範囲で再開する。

音声は要求どおり初期ON。ただしブラウザの音声付き自動再生制限を考慮し、最初のPlay操作をユーザー操作として扱う。ブロックされた場合は動画領域に再生操作を表示する。自動再生を必ず成功させる仕様にはしない。

埋め込み不可、削除済み、地域制限、認証が必要な動画等は読み込み失敗として別候補へ移る。候補が全て失敗した場合は写真へ戻す。API利用で広告・YouTube操作UI等を排除できるとは仮定しない。

1分割時は動画が選ばれると画面全体が動画となり、写真との同時表示はできない。写真のみを楽しみたい場合は動画を無効化できる。この動作はレビュー対象。

## 9. BGMとSpotify（保留）

要求：BGMにSpotifyを選択し、設定キーワードからプレイリストを自動選択して写真閲覧中に音楽を流す。「Spitify」はSpotifyとして整理した。

ただしSpotify公式Developer Policyには、音源とスライドショー等の視覚媒体の同期禁止、他の音声との重複禁止、他サービスのコンテンツとの統合に関する制限がある。要求どおりの組み込みBGMを提供可能とは確定しない。Spotify実装は保留とし、サービス側に確認が取れて採用条件が成立した場合のみ仕様を再確定する。Web API / SDKのアカウント条件・利用可能な検索機能・端末対応もその時点で確認する。

レビュー用の代替提案：利用権限のあるローカル音声ファイルを選択してBGMとしてループ再生する。対応候補はMP3 / AAC。初期OFF。YouTube音声がONの場合はBGMを一時停止し、同時音声を避ける。音楽を写真の切り替えに同期させず、連続再生する。代替案はユーザーの合意後に採用する。

## 10. 状態、保存、エラー処理

Google Driveでは、起動 → 記憶した場所・有効な同一タブ認証を復元 → 最初の写真から自動再生 → 残りを順次取得、を基本とする。認証がない場合は再接続のユーザー操作後に自動再生する。Google認証・音声再生のブラウザ制限を回避しない。ローカルフォルダ・サンプルは従来のPlay操作を維持する。

日付、分割数、時間、エフェクト、音声設定、ソースの種類と識別情報を端末内に保存する。写真本体は永続コピーせず、アクセストークンを通常のlocalStorage設定保存領域へ保存しない。同一タブのsessionStorageに限り短期間のトークン・有効期限・クライアントID・スコープを保存し、復元時に整合性と期限を検査する。期限切れ・401・解除では削除する。新しいタブや期限切れの場合はユーザーによる再接続が必要。端末間の設定同期は対象外。接続解除では認証状態と自動復元用の場所・写真メタデータを破棄する。

| 状況 | 表示・動作 |
|---|---|
| 日付・時間の入力不正 | 理由を表示し適用しない |
| 選択キャンセル | 既存の設定を維持 |
| フォルダ読み取り権限なし | 再選択／再許可を案内 |
| 対象写真・動画なし | 期間またはフォルダ変更を案内 |
| 個別画像の破損・未対応形式 | スキップし件数を通知 |
| ネットワーク切断 | 表示済み写真を保持し、再接続操作を案内 |
| Drive認証切れ | 再認証を案内、可能なら表示済み写真を保持 |
| API回数制限 | バックオフし、連続リクエストを避ける |
| 音声再生ブロック | ユーザーによる再生操作を表示 |

ローカル写真を外部にアップロードしない。Google / YouTube連携にはそれぞれのサービスへの通信が発生する。ファイル名・フォルダ名はテキストとして安全に表示する。

## 11. 実装方針（レビュー対象）

HTML5のクライアントアプリを中心とし、画面、メディア一覧、更新スケジューラ、写真表示、YouTube再生、ソース接続を分離する。ローカルとDriveを共通のメディア形式（日付、フォルダ名、ソースID、種類、取得参照）へ変換する。

Google OAuthの登録、API有効化、許可された配信元の設定が必要。HTMLファイルをダブルクリックするだけで全機能が使える構成は想定しない。フレームワーク・配信方式・必要な認証補助サーバーの有無は仕様レビュー後に決定する。GitHubリポジトリは本作業では読み取りが成功せず、既存コード・構成を確認できていないため、実装前に確認する。

## 12. 受け入れ条件

1. 設定アイコンで左ペインが開閉し、閉じるとグリッドが利用可能領域へ広がる。
2. 指定した開始日・終了日を含むフォルダだけが対象となり、不正な日付や逆転した期間は適用できない。
3. 1・2・3・4・6・8の全分割が表示され、画面回転・サイズ変更後も領域数が維持される。
4. 4分割・15秒で概ね3.75秒ごとに1領域が更新され、各領域は概ね15秒周期となる。通信失敗時でも残りの表示が継続する。
5. Stopで自動更新と動画が止まり、Playで周期が再開する。
6. 写真切り替えにクロスフェードが適用され、フォルダ名が各領域の中央下に白いゴシック太字で読みやすく表示される。
7. Windowsで許可したローカルフォルダと、各対象端末で認証したGoogle Driveフォルダから読み込める。
8. YouTubeが1領域で再生され、同じ動画を保持したまま当該領域の更新時に再生位置が変わる。音声ONと再生ブロック時の再試行を確認する。
9. 対象0件、権限拒否、破損画像、埋め込み不可動画、認証切れで操作不能にならない。
10. 全画面対応環境では全画面になる。非対応環境は最大化された閲覧表示となる。
11. Windows、iPad、iPhoneの実機で画像表示、操作、認証、音声、回転を確認する。実機未検証項目は完了扱いにしない。
12. BGMは採用した方式が確定してから受け入れ条件を追加する。

## 13. レビューで決める事項

優先して確認したい項目：

- Spotifyを保留し、初期版はBGMなし、またはローカル音声BGMとするか。
- iPad / iPhoneはGoogle Driveを主なフォルダ接続方式としてよいか。
- フォルダ名は画面全体に1つではなく、各領域の中央下に表示してよいか。
- 動画は自動で1件を選び、明示操作まで同じ動画を維持する方針でよいか。1分割で動画が全面表示になる動作も含む。

その他の提案は本文の初期値を基本とする。添付図にある期間スライダー、人物フィルター、最大3フォルダ選択は、初期版に含めるかを別途決める。人物フィルターにはタグや顔認識等の追加データ設計が必要となる。
